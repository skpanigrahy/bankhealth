4. The bigger architectural picture

This is actually becoming a very good structure for your Branch Health application:

BRANCH HEALTH
                         │
                 Branch Manager View
                         │
        ┌────────────────┼─────────────────┐
        │                │                 │
   Branch Actions    Branch Status    Insights
        │                │                 │
        ├─ Control Exceptions → BMD
        ├─ Branch Dashboard  → BMD
        ├─ ICSC Reset        → BMD
        ├─ Cash Management   → Teller
        ├─ Banker Notification → Banker System
        │
        ├─ Tech Readiness
        │      ├─ ATM
        │      ├─ Tablets
        │      ├─ Workstations
        │      ├─ Network
        │      ├─ Backup connectivity
        │      └─ Channel systems
        │
        ├─ OSAT / CX
        ├─ Convenience
        ├─ One Chase Sales
        ├─ Banker Availability
        └─ Nearby Branches

The key principle

Branch Health is the aggregation/orchestration layer.

It should not become the system of record for these individual business domains.

Each domain should point to its authoritative source, and Branch Health brings the information together into one daily operational view for the Branch Manager.

5. What I would tell Copilot / your development team

The implementation requirement can be summarized very simply:

> Do not build the Branch Health backend around the current mock-data structure or assume one source system per segment. The UX defines the required business information, while the backend must integrate with the appropriate systems of record for each data point. For Tech Readiness in particular, do not use Eagle as the assumed long-term source. Validate the authoritative sources with Champa/Srini, including BLDS, BDIS, ATM, Channel Management, Branch OS/Linq and other relevant systems. Keep the integration layer modular so individual source systems can be replaced without changing the Branch Health UI or business layer.



That last point is especially important because Eagle is already on a decommission/recovery path. You don't want your new Branch Health application to inherit that dependency.
